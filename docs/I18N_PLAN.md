# i18n Foundation Plan — Georgian (ka) localization

> Contribution tracked in upstream issue #220. First locales: `en` (source) and `ka` (Georgian).
> This document is the architecture proposal; no components are refactored in this PR.

## 1. Scope of what must be localized

| Layer | Where | Count | Format today |
|---|---|---|---|
| App UI strings | `app/page.tsx`, `app/scene.tsx`, `app/model-download.ts` | 83 | Hardcoded inline JSX / string literals |
| Shared UI library a11y strings | `components/ui/*.tsx` | 20 | Hardcoded (`sr-only` text, `aria-label`, defaults) |
| Agent-tool descriptions | `app/agent-tools.ts` | 6 | Hardcoded (AI-agent facing — proposal: keep `en`, see §7) |
| Anatomical system names + descriptions | `app/anatomy.ts` → `SYSTEMS[]` | 15 names + 15 descriptions | TS array of `{id,name,color,description}` |
| Featured-organ explanations | `app/anatomy.ts` → `EXPLANATIONS` | 9 | `Record<lowercase-name, text>` |
| Anatomy concept names | `public/models/atlas.json` → `concepts[]` | **3,432** | `{id:"FMA…", name:"…", elements:[partId…]}` |
| Anatomy part (mesh) names | `public/models/atlas.json` → `parts[]` | **2,234** | `{id:"FJ…", name:"…", conceptId, system, …}` |

Full per-file inventory (109 strings): `locales/en.json`, generated by `scripts/build-en-inventory.py`.

## 2. Locale file structure

```
locales/
  en.json            # source of truth, all UI namespaces (this PR)
  ka.json            # mirrors en.json key-for-key (follow-up PR)
  systems.en.json    # 15 system names + descriptions (extracted from app/anatomy.ts)
  systems.ka.json    # Georgian translations
  anatomy.ka.json    # { "FMA3710": {"ka": "…", "aliases": ["…"]}, … } — data-level, follow-up PR
```

`en.json` namespaces: `common`, `header`, `controls`, `panels`, `search`, `details`, `about`,
`loading`, `errors`, `a11y`, `agent`, `ui`. `ka.json` must mirror the same shape; a CI check
(`scripts/check-locales.py`, planned) will fail on missing/extra keys.

### Key naming conventions
- `namespace.camelCaseKey`, e.g. `controls.explodeAnatomy`, `a11y.closeSearch`.
- Interpolation: `{name}` placeholders — `panels.showOnlySystem`: `"Show only {system}"`.
- Plurals: ICU-lite pattern `{count, plural, one {piece} other {pieces}}`, resolved by a
  ~20-line formatter (Georgian has no plural morphology — `one`/`other` collapse to one form).
- Caps-styled labels (CSS `text-transform` candidates) stay as authored in the locale file;
  no runtime casing transforms, so ka text is never uppercased by code.
- Anatomical proper nouns and dataset brands (`Human Atlas`, `BodyParts3D`, FMA/FJ identifiers)
  are marked non-translatable.

## 3. Runtime approach — lightweight typed React context (no library)

Maintainer preference for a heavy library (react-i18next/FormatJS) is **pending** in issue #220;
this plan deliberately proposes a zero-dependency approach so the app keeps its current
bundle profile:

```ts
// app/i18n.tsx (follow-up PR)
type Messages = typeof en;                       // full type inference from en.json
type Locale = 'en' | 'ka';
const I18nContext = createContext<{locale: Locale; t: (key: string, vars?: Record<string, string|number>) => string}>()
<I18nProvider initialLocale={detect()}>          // localStorage → navigator.language → 'en'
```

- `t('search.noMatches')` — dot-path lookup with a typed union of valid keys (generated from
  `en.json` via a small `scripts/gen-i18n-types.ts`).
- `ka.json` is loaded lazily (`import()`); `en` is bundled as the fallback — missing ka keys
  fall back to en per-key, never crash.
- String count is tiny (109), so no message-format compiler is needed; the formatter handles
  `{var}` substitution and the one plural case.

## 4. Anatomy data-level localization (the 3,432 concepts)

The atlas data (`public/models/atlas.json`, 1.3 MB) is **not** modified — it stays the
geometry/metadata source of truth. Localization is an overlay:

```jsonc
// locales/anatomy.ka.json
{
  "FMA7140": { "ka": "ბეჭვის ძვალი", "aliases": ["femur", "thigh bone"] }
}
```

- **Display**: when `locale === 'ka'` and an entry exists, UI shows `ka`; otherwise the en/FMA
  name (most of the 3,432 concepts are specialist Latin/FMA terms that correctly remain in
  Latin script — priority is the ~300 commonly searched structures: organs, major bones,
  vessels, nerves — plus all 15 system names/descriptions and the 9 `EXPLANATIONS` entries).
- **Search**: matching runs against `ka` + `aliases` + original en name + FMA id, so both
  Georgian and English/Latin queries find the same concept (`search aliases` requirement).
- The overlay is keyed by stable `conceptId` (`FMA…`) / part `id` (`FJ…`), never by English
  name, so upstream data updates don't break translations.
- Systems/explanations: `SYSTEMS` and `EXPLANATIONS` move out of `app/anatomy.ts` into
  `locales/systems.{en,ka}.json`; ids and colors stay in TS.

## 5. Language switcher & persistence

- Placement: `nav.top-actions`, next to the About button — a compact ghost `Button` showing
  `EN`/`KA` (globe icon optional), matching the existing minimal chrome. On mobile it lives
  inside the same top bar; no new panels.
- Persistence: `localStorage["human-atlas-locale"]`; initial detection order:
  stored value → `navigator.language` starts with `ka` → `en`.
- Switching locale is instant (no reload): React context re-renders UI strings; the 3D scene
  needs no rebuild except hover-tooltip text, which reads from the localized lookup.
- `<html lang>` is updated on switch for screen readers.

## 6. Phased PR strategy

1. **PR 1 — Foundation (this PR)**: `docs/I18N_PLAN.md`, `locales/en.json` (complete inventory),
   `scripts/build-en-inventory.py`. Zero runtime changes.
2. **PR 2 — Runtime**: `app/i18n.tsx` provider + `t()`, type generation, language switcher,
   localStorage persistence; refactor `app/page.tsx`, `app/scene.tsx`, `app/model-download.ts`
   to consume `t()`. App still ships en-only — no user-visible change.
3. **PR 3 — ka UI**: `locales/ka.json` + `locales/systems.ka.json`, extraction of
   `SYSTEMS`/`EXPLANATIONS`, ka system names/descriptions/explanations live.
4. **PR 4 — ka anatomy data**: `locales/anatomy.ka.json` for priority concepts + alias-aware
   search; locale-file parity CI check.
5. **PR 5 (optional)**: shared `components/ui/*` namespace wiring, agent-tool localization
   decision.
